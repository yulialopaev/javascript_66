/*
1. Зачем вообще разбивать программу на файлы?
Чтобы код было удобнее читать и каждый файл отвечал за свою зону ответственности.
В таком случае, если есть четкая структура, редактировать программу кусочками становится намного легче - так как
не надо переписывать всё приложение.

2. Что такое модуль?
Модуль - это часть приложения, отдельный JS файл со своей областью видимости, который отвечает за свою функционал.
Может явно предоставлять значения другим модулям через экспорт и получать значения из других модулей через импорт.

3. Чем import отличается от подключения десяти <script> в HTML?
Импорт включает в себя только те данные или функции, которые необходимы в модуле. Script подключает весь модуль
целиком к index.html.

4. Что делает export?
Export позволяет открыть возможность для других модулей использовать функции или переменные. Экспортировать нужно то,
что понадобится другим модулям.

5. Что делает import?
Import происходит внутри модуля, которому необходимы данные и "забирает" экспортированные данные из другого модуля

6. Что такое dependency?
Зависимость. Файл 2, который импортирует данные из файла 1, зависит от файла 1.

7. Что такое named export?
Export, который подписывается у каждой функции или переменной отдельно (например, export const =...
или export function...). Именных экспортов в файле может быть несколько

8. Что такое default export?
Export, который пишется в конце файла или непосредственно перед функцией (export default function...) и он в
рамках модуля может быть только один.

9. Почему у named import используются { }?
Для перечисления всех конкретных переменных или функций, которые импортируются. Показывают, что импорт именованный.
В default import скобки не используются.

10. Что означает ./?
Необходимый файл находится в той же папке

11. Что означает ../?
Файл находится на уровень выше

12. Почему app.js не должен содержать всю программу?
Чтобы его было легко читать и файл не был перегруженным. В нём будут прописано, от каких модулей зависит app.js.

13. Почему внутреннюю вспомогательную функцию необязательно экспортировать?
Потому что она не нужна для работы других модулей. Нет смысла экспортировать то, что не используется.

14. Зачем type="module"?
Чтобы дать понять index.html, что у нас будет модульная структура, и дать возможность её осуществить. При указании
type="module" не обязательно использовать defer.

 */
